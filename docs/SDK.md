# SDK UNET-GAME

SDK — исходные модули sjasmplus, которые игра включает в свою программу
вместе с `UNETGAME.INC`. Они загружают DLL, вызывают её экспорты напрямую,
допускают входы по фиксированным квотам (ТЗ §5.1), ведут `now_ms` и
выполняют порядок входа и выхода ТЗ §7. Ядро DLL не знает о SDK: всё, что
касается DSS, прерываний, CTC и квот, лежит здесь.

| Файл | Содержимое |
|---|---|
| `sdk/loader/ugload.asm` | `UG_LOAD`, `UG_FREE`: загрузка через libman, страница и база DLL, сверка с самой библиотекой |
| `sdk/gateway/ugate.inc` | Раскладка блока шлюза, профиль приложения, коды, стоимости обвязки |
| `sdk/gateway/ugate.asm` | Прямые вызовы, `UG_INIT_ENV`, допуск STEP, входы из ISR, такт периода, выход |
| `sdk/time/ugtime.asm` | Адаптеры времени `FIXED_SCHEDULE` и `APP_COUNTER` |
| `sdk/example/netdemo.asm` | Пример смешанного обслуживания (ТЗ §7) и программа стенда M |
| `third_party/libman` | git-сабмодуль libman (загрузчик DLL DSS), подключается через `LIBMAN_DIR` |

Перед `INCLUDE "gateway/ugate.inc"` игра задаёт `UG_BLOCK EQU <адрес>` —
блок шлюза (192 байта, выровнен на 256, постоянно видимая RAM ниже `#C000`;
первый байт — общий замок ISA) и `DEFINE UG_DLL_WIN 1` (окно, для которого
релоцирована DLL; 1 или 2). Пути включения: `-I sdk -I include -I <LIBMAN_DIR>`.

## Порядок работы игры

1. **До игры**, пока работает IM1 и DSS:
   `UG_GW_INIT` (A = текущий `#1FFD`, E = текущий `#9FBD`) →
   `UG_LOAD` (имя файла; libman вызывает INIT) → игра обнуляет регион
   контекста → `UG_INIT_ENV` (IX = блок INIT_CONFIG, HL = профиль).
2. **Прерывания.** Игра ставит свою таблицу IM2, программирует свой таймер
   (в примере CTC1: `#A7`, константа 164 → 1999,238 мкс при 21 МГц),
   вызывает `UGT_INIT` (HL:DE = начальное `now_ms`), затем `UG_START` и `EI`.
   После `IM 2` вызовы DSS запрещены (обслуживание DSS IM1 остановлено, как
   в Worms).
3. **Обработчик таймера** (IFF = 0): `UG_TICK` → `UG_ISR_NET` с
   `UNETG_SRC_TIMER` → `UGT_TICK` → `EI` / `RETI`. Другие обработчики:
   кадр — `UG_ISR_FRAME`, клавиатура — `UG_ISR_KEY`, звук — `UG_ISR_CBL`
   (только флаг), IRQ карты — `UG_ISR_NET` с `UNETG_SRC_CARD_IRQ`. Каждый
   обработчик сначала обслуживает своё устройство.
4. **Основной цикл:** `UG_STEP` (допуск из квоты main), события
   (`NEXT_EVENT`), RX/TX — всё через `UG_CALL`. Во время паузы игры цикл
   продолжает `UG_STEP` и события: часы, периоды, опрос и TCP идут дальше.
5. **Выход:** `UG_SHUTDOWN` (DE = предел в мс) до OK → игра останавливает
   свой таймер, восстанавливает I и `IM 1` → `UG_EXIT` (A = байт замка,
   ожидается 0) → `EI` → `UG_FREE` (FINI через libman) → возврат в DSS.

## Загрузчик

`UG_LOAD` вызывает `LIBMAN.l_load` для окна `UG_DLL_WIN`. Из записи
`LIBMAN.lib_table` берутся id блока DSS и база. Физическую страницу даёт
`IN` порта окна после `SetWin1/2` (DSS `#39`/`#3A`); затем окно
возвращается к прежней странице. Две сверки (ТЗ §8): `GET_INFO.image_base`
совпадает с базой libman, 32 байта `l_info` совпадают с заголовком L1 по
этой базе. Несовпадение — `UG_LD_BASE` / `UG_LD_HEADER` и `l_free`; отказ
libman — `UG_LD_LIBMAN` (B = `LIBMAN.l_reason`). Раскладка `lib_table` —
внутренняя: `ASSERT LIBMAN.VERSION == 0x0104`.

Программа, разместившая DLL сама (стенд Z), вызывает `UG_ATTACH`
(A = страница, H = старший байт базы).

## Шлюз

| Процедура | Где | Вход → выход | Портит |
|---|---|---|---|
| `UG_GW_INIT` | main, до прерываний | A, E = тени `#1FFD`, `#9FBD` | AF, BC, DE, HL |
| `UG_ATTACH` | main | A = страница, H = база | AF, HL |
| `UG_CALL` | main и ISR | B = экспорт; A, DE, IX, IY по ABI → A, DE, HL, F экспорта | BC |
| `UG_INIT_ENV` | main | IX = INIT_CONFIG, HL = профиль → A = статус, `UGW_ENV` | BC, DE, HL |
| `UG_START` / `UG_STOP` | main | периоды, допуск и входы ISR вкл. / выкл. | AF, HL |
| `UG_STEP` | main | → A = статус STEP или `UG_ST_EARLY/REFUSED/OFF`, DE, L | BC, HL |
| `UG_NOW` | main | → HL = `now_ms[15:0]`, DE = `[31:16]` | AF, B |
| `UG_TICK` | ISR таймера | такт: опрос, разнесение STEP, CBL, период | AF, DE, HL |
| `UG_ISR_NET` | ISR | A = источник | AF, BC, DE, HL |
| `UG_ISR_FRAME/KEY/CBL` | ISR | — | AF, BC, DE, HL |
| `UG_SHUTDOWN` | main | DE = предел, мс → A | BC, DE, HL |
| `UG_EXIT` | main, DI | → A = байт замка | HL |
| `UG_SNAPSHOT` | main | DE = буфер на 128 байт | AF, BC, DE, HL |

Все сохраняют IX и IY, кроме явно отмеченного; ни одна не пишет PIO и CTC.

**Прямой вызов.** `UG_CALL` переходит на `base + 0x20 + 3 × B`. Если в окне
DLL другая страница (игра держит там свои данные, или прерывание пришло в
середине работы игры), шлюз ставит страницу DLL и возвращает прежнюю.
Стоимость ~5 мкс вместо ~170 мкс у `l_call` с DSS SETWIN.

**`UG_INIT_ENV`** читает GET_INFO и профиль, считает бюджеты, стоимости и
квоты, заполняет поля INIT_CONFIG, принадлежащие шлюзу (`mode`,
`timing_mode`, `worst_poll_gap_us`, `worst_step_gap_ms`, `step_budget_us`,
`isr_budget_us`, `time_read_cost_us`, `isa_lock_ptr`, указатели теней), и
вызывает INIT_CONFIG. Остальные поля (карта, адреса, регионы, сроки, стек
ISR) задаёт игра.

| Поле профиля | Смысл |
|---|---|
| `UGP_TICK_US`, `UGP_TICK_FRAC` | Длина тика: целые мкс и 1/256 мкс |
| `UGP_PERIOD_TICKS` | Тиков в бюджетном периоде (10: период 19,99 мс) |
| `UGP_POLL_TICKS` | Тиков между гарантированными опросами (1) |
| `UGP_STEPS` | STEP из квоты main за период |
| `UGP_STEP_GAP_MS` | Гарантированный худший разрыв между вызовами STEP |
| `UGP_CARD_N` | Входов IRQ карты за период (0: маршрута нет) |
| `UGP_STEP_BUDGET`, `UGP_ISR_BUDGET` | Бюджеты тел (0: `min_useful`, пустой опрос + возврат) |
| `UGP_Q_SERVICE` | Служебная квота за период |
| `UGP_TARGET` | Цель сети за период (ТЗ §5: 2000) |
| `UGP_OTHER_ISR` | Самый длинный чужой обработчик, мкс |
| `UGP_FLAGS` | `UGPF_RELAXED` (принять квоты выше цели), `UGPF_FRAME_PER` (период от кадра) |
| `UGP_MODE`, `UGP_TIMING` | `UNETG_MODE_*`, `UNETG_TIMING_*` |

Результат в `UGW_ENV`: `UG_ENV_OK` (сумма квот ≤ цели), `UG_ENV_OVER`
(выше цели, принят по `UGPF_RELAXED`), `UG_ENV_REFUSED`, `UG_ENV_GAP` (тик
опроса плюс 200 мкс DI плюс чужой обработчик больше `poll_gap_us`),
`UG_ENV_BUDGET`, `UG_ENV_INFO`, `UG_ENV_CONFIG` (INIT_CONFIG отказал,
A = его статус), `UG_ENV_PROFILE`.

**Допуск** (ТЗ §5.1). Квоты на период: опрос = опросов за период × стоимость
опроса, IRQ карты = `UGP_CARD_N` × стоимость опроса, main = `UGP_STEPS` ×
стоимость STEP, служебная — из профиля. Стоимость входа = бюджет тела +
обвязка шлюза; она списывается до входа и не возвращается.

- `UG_STEP` под одной короткой DI-секцией проверяет разнесение (не чаще
  одного STEP за `период / UGP_STEPS` тиков; ранняя попытка бесплатна) и
  квоту main, списывает полную стоимость и записывает активный вызов. STEP
  идёт без предзахвата ISA: ядро берёт замок на каждую порцию, звук не
  ждёт целый STEP.
- `UG_ISR_NET` проверяет срок опроса и квоту источника, затем делает
  test-and-set замка (владелец 2). Занятая шина: стоимость `UG_BUSY_PATH_US`
  из квоты источника, ядро не вызывается, опрос остаётся должным
  (следующий источник — клавиатура или кадр — может его выполнить).
  Свободная: полная стоимость, стек ISR из INIT_CONFIG, `STEP_ISR` с
  признаком предзахвата, освобождение замка после возврата ядра.
- Отказ из-за квоты оплачивает служебная квота; IRQ карты при этом
  маскируется программно до опроса в следующем периоде.
- На границе периода каждая квота начинается заново, квота main — за
  вычетом полной стоимости ещё идущего STEP; остаток не переносится.

**Стоимости обвязки** (стенд Z, 21 МГц; константы в `ugate.inc` с запасом):

| Путь | Замер | Константа |
|---|---:|---:|
| `UG_ISR_NET` вокруг STEP_ISR | 29,1 мкс | `UG_OVH_ISR_US` 35 |
| `UG_STEP` вокруг STEP (со сменой страницы окна) | 39,4 (46,1) мкс | `UG_OVH_STEP_US` 50 |
| Отказ по занятой шине до входа в ядро | 19,6 мкс | `UG_BUSY_PATH_US` 22 |
| Отказ в допуске | — | `UG_REFUSE_US` 15 |
| `UG_TICK` (с границей периода) | 27,1 мкс | — |
| `UGT_TICK`, FIXED_SCHEDULE | 11,3 мкс | — |
| `UGT_TICK`, APP_COUNTER (с повтором) | 17,8 мкс | `UGT_READ_US` 20 |

Отказ по занятой шине через шлюз (19,6 мкс) укладывается в цель ТЗ §5.1
для BUS_BUSY (≤ 25 мкс); BUS_BUSY самого ядра — 24,8 мкс (GET_INFO 25).

**Сумма квот и цель 2000 мкс.** С текущим ядром цель недостижима: опрос
стоит 95–105 + 35 мкс (бюджет STEP_ISR — пустой опрос из GET_INFO плюс
возврат), STEP — 480–500 + 50 мкс. Десять опросов и два STEP за период
дают 2500–2600 мкс. Профиль примера ставит `UGPF_RELAXED`; превышение
видно в `UGW_ENV` и `UGW_SUM`. Пропускная способность через шлюз зависит
от числа STEP за период (`node tools/dev/sdk_rate.js [--budget us]
[--isr us]`, эхо 2 КиБ в обе стороны, стенд Z):

| STEP за период | GTCPRTL | GTCP509B | GUDP509B | GTCPESP | GUDPESP | Сумма квот |
|---:|---:|---:|---:|---:|---:|---:|
| 2 | 0,58 КиБ/с | 0,58 | 1,13 | 0,19 | 0,27 | 2500–2600 мкс |
| 5 | 1,45 | 1,45 | 2,83 | 0,45 | 0,67 | 4100–4250 мкс |
| 10 | 2,86 | 2,86 | 5,62 | 0,91 | 1,34 | 6750–7000 мкс |

Ядро тратит на сегмент TCP 100 байт 26 STEP до TX_DONE и 38 до эха
(536 байт — 54 и 77). Пример SDK по умолчанию берёт 5 STEP за период
(около 21 % процессора).

## Адаптеры времени

`now_ms` хранится в блоке шлюза; основной цикл читает его через `UG_NOW`.

- **FIXED_SCHEDULE.** Тик прибавляет свою настоящую длину: целые мс и
  остаток в мкс заранее разложены `UG_INIT_ENV`, доли мкс — в байте
  1/256. Счётчики во время игры не читаются. На стенде Z за 20 с ошибка
  ≤ 2,5 мс (фаза тика при чтении); в MAME — 1,000 мс `now_ms` на мс.
- **APP_COUNTER** (цепь CTC2 → CTC3 игры, 875 кГц, /112, /156). Тик читает
  CTC3, CTC2, CTC3; при смене CTC3 — ещё одно чтение, при второй смене
  отметки нет (следующий тик догонит). Фаза берётся из двух таблиц по
  значению CTC3, дельта по модулю 17 472 публикуется как 32-битный счётчик
  отсчётов (только ISR). В мс его переводит `UG_NOW` в основном цикле.
  Стоимость выборки с повтором ≤ 17,8 мкс (норматив 20). Адаптер только
  читает CTC; программирует цепь игра. В MAME holub цепь на 875 кГц не
  считает, поэтому APP_COUNTER проверен только на стенде Z.

## Пример NETDEMO

`sdk/example/netdemo.asm` → `NETDEMO.EXE` (DSS). Карта WIN2
(`tools/mame/mkcfg.js --prog netdemo`): код с `0x8100`, контекст `0x9C00`,
слоты TX/RX, очередь событий, кольцо UART `0xB040`, блок шлюза `0xB300`,
таблица IM2 `0xB400` (I = `#B4`, байт `#B5`, обработчик по умолчанию
`0xB5B5`), стек ISR `0xB600`, отчёт `0xB700`, главный стек `0xBB00..0xBFF0`.
Тик — CTC1, кадр (`#FF`) только считается и даёт дополнительную возможность
опроса. Секундомер на CTC2/CTC3 (таймер /16) пишет строку `TIMING`.

Сценарии (`-DSCEN`): L — загрузка, сверка, освобождение; E — эхо 300 байт;
S — поток 8 КиБ; P — сервер закрывает соединение; D — SHUTDOWN при
открытом канале; W — пауза 2 с между двумя эхо. `-DUG_STEPS=n` — STEP за
период. Запуск: `tools/mame/run_m.py --prog netdemo gtcpesp E`.

## Ограничения v1

- Маршрута IRQ карты к PIO нет ни на одной известной плате, ни в MAME;
  шлюз не пишет PIO и IM2 маршрута, `MASK_ROUTE` и исчерпание квоты карты
  ставят только программную маску. Ядро обслуживает AUTO через POLL, пробы
  IRQ нет (`CAP_PROBE` не публикуется).
- Полный путь ISR с ядром на стенде Z 184–195 мкс (норматив ТЗ §3:
  200 мкс), но гарантия по бюджетам не сходится: тело STEP_ISR до 145 мкс +
  обвязка 35 + такт 27 + часы 11 + вход и RETI ≈ 223 мкс (`todo`).
- В MAME тиковый ISR занимает до 470 мкс, допущенный `UG_STEP` с
  прерываниями — до 1,7 мс (ожидания памяти MAME, см. MEASUREMENTS).
- Кадровый импульс FPGA (~9 мкс в MAME) теряется под DI; источник периода —
  таймер. Переключение на кадр (`UGPF_FRAME_PER`) — после замера на Ж.
- Ядро не держит разрыв STEP 20 мс у TCP-сборок (MEASUREMENTS, долг).

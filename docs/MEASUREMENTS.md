# Измерения стоимости (веха 0)

Все числа ниже получены на стенде Z (`tools/harness`) при модели 21 МГц
без ожиданий DRAM и с 8 дополнительными тактами на каждое обращение к ISA.
Это проектные верхние оценки для прототипа, а не замеры на железе. Замеры
на MAME (графа M) и реальном Sprinter (графа Ж) **не выполнены**: программы
`tools/measure` ещё не написаны, калибровка ожиданий ISA и DRAM отсутствует.

## Единица бюджета

Ядро не читает часы. Бюджет вызова один раз переводится в «микросекунды
21-МГц процессора» по полю `INIT_CONFIG.cpu_khz`; все константы стоимости
выражены в этих единицах. Работа, которая не помещается вместе с самым
дешёвым путём возврата, не начинается (`TAKE`, `BUDGET_BYTES`).

## Константы и наблюдения стенда

Значения выставлены по ревизии бюджета (`tools/dev/audit.js`): для каждого
списания сравнивается реальная работа до следующего списания с резервом.

| Константа | Резерв | Наблюдение на стенде |
|---|---:|---|
| `PROF_STEP_BASE_US` loopback / карты | 140 / 170 | Пролог, часы, сроки из кэша, эпилог: 117–129 мкс |
| `COST_TMR_FULL` | 120 | Оценка таймеров и полный пересчёт сроков: до 86 мкс + часы |
| `COST_PORTION` | 110 | Обвязка порции 49 мкс + короткий шаг карты; пустой опрос 63–107 |
| `COST_BRINGUP` | 190 | Шаг подъёма (16 байт ID или 2 команды таблицы) |
| `COST_CHUNK` | 230 | 40 байт из FIFO со слитной суммой: 216 мкс |
| `COST_CLASSIFY` / `COST_ACCEPT` / `COST_STORE` | 200 / 290 / 170 | Ethernet/IP; транспорт; размещение в кольце (всего до 354 мкс, поэтому три фазы) |
| `COST_FINISH` | 260 | Вердикт суммы + разбор TCP |
| `COST_TP_PULL` | 230 | Заголовок из шаблона: 175–204 мкс (было 327 до шаблона) |
| `COST_TX_BEGIN` / `COST_TX_WAIT` | 250 / 150 | Преамбула и 54 байта заголовка; завершение и уведомление |
| `COST_TEMPLATE` | 240 (TCP), 170 (UDP) | Построение шаблона заголовка: 151–222 мкс |
| `COST_TCP_STEP` / `IDLE` / `DATA` | 220 / 60 / 140 | Таймеры TCP; простой шаг; выбор сегмента данных |
| `COST_UDP_STEP` / `IDLE` | 170 / 80 | Таймеры UDP; простой шаг |
| `COST_EVENT` / `COST_TXSCAN` | 60 / 80 | Публикация TX_DONE ≈55; проход по слотам до 76 |
| `COST_LOOP_ITER` + `COST_LOOP_FIXED` | 80 + 110 | Постоянная часть порции loopback ≈171 мкс |

Самая длинная секция с запрещёнными прерываниями — около 140 мкс (порция
FIFO 40 байт со слитной суммой); порция 64 байт давала 220 мкс и была
уменьшена. Прогоны: перебор GLOOP 260…500 мкс — 0 превышений (максимум
97,7 % бюджета); сквозные прогоны GTCP509B/GUDP509B при бюджете 500 мкс —
0 превышений (худший шаг 491 и 466 мкс).

Производительность на стенде при бюджете STEP 500 мкс каждые 10 мс: подъём
3C509B 39 шагов, соединение TCP 29 шагов, эхо 300 байт 45 шагов, закрытие
27 шагов.

## Известные ограничения и долг

- При 7 МГц минимальный полезный бюджет (270–310 мкс при 21 МГц) втрое
  больше и не помещается в предельные 500 мкс тела STEP: `INIT_CONFIG`
  возвращает `UNSUPPORTED_TIMING`. Профиль v1 требует турбо 21 МГц.
- Постоянная часть STEP (≈120–150 мкс) и тяжёлые статьи (разбор сегмента,
  сборка заголовка) велики из-за индексной адресации контекста. При бюджете
  STEP 300 мкс, как в примере ТЗ, Ethernet-сборки прогресса почти не делают;
  рабочий бюджет сейчас 450–500 мкс. Снижение стоимости — обязательная
  работа вех M2/M3.
- Ожидания DRAM в турбо и реальная длительность циклов ISA на Sprinter
  неизвестны; до замеров стенд их не моделирует.
